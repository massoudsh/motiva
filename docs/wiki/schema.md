# Wiki Schema — قوانین این پایگاه دانش

> این فایل را ایجنت خودش می‌خواند و می‌نویسد. هرگاه عمیق‌تر فهمید،
> همین فایل را به‌روزرسانی می‌کند. این تنها سند **بالا به پایین** wiki است.

## ساختار پوشه
```
docs/wiki/
  schema.md      # این فایل — قوانین
  overview.md    # یک‌نگاه کلی پروژه (≤۴۰۰ کلمه)
  index.md       # کاتالوگ همه صفحات، گروه‌بندی‌شده
  log.md         # تاریخچه append-only
  entities/      # هر entity مهم یک صفحه (مدل داده، صفحه کلیدی، ماژول)
  concepts/      # patternها، flowها، تصمیم‌های معماری
  sources/       # (اختیاری) خلاصه فایل‌های خام کد که چندجا ارجاع داده می‌شوند
```

## لینک‌گذاری (Obsidian-style)
- از `[[entities/user]]` برای ارجاع به صفحه دیگر استفاده کن — بدون پسوند `.md`.
- نام صفحات: lowercase + hyphen (مثال: `auth-flow.md` نه `Auth Flow.md`).
- wikilinkهای نمونه داخل بک‌تیک/code block لینک واقعی محسوب نمی‌شوند.

## چه وقت صفحه جدید بساز
- فقط اگر **≥۳ جای دیگر** قرار است به آن لینک بدهند، یا concept مستقلی با حجم قابل‌توجه است.
- در ۹۰٪ موارد به‌جای فایل جدید، **صفحه موجود را آپدیت کن**.
- هرگز صفحه‌ی trivial نساز.

## ساختار صفحه‌ی entity
```markdown
# {نام}

> یک‌خطی توضیح هدف.

## مسئولیت‌ها
- ...

## وابستگی‌ها
- [[concepts/xxx]] — چرا

## قراردادها / Edge cases
- ...

## منابع کد
- `path/to/file.ts:42` — کلاس اصلی
```

## Lint دوره‌ای (وقتی کاربر گفت "ویکی رو بازبینی کن")
1. orphan pages — لینک بده یا حذف کن.
2. broken link — صفحه‌ی گمشده را بساز یا لینک را حذف کن.
3. تناقض بین صفحات — flag کن، بهترین حدس را انتخاب کن و در log ثبت کن.
4. صفحات کهنه (کد مرتبط تغییر کرده ولی صفحه آپدیت نشده) — بازخوانی و sync.
