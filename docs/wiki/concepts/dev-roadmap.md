# Dev Roadmap

> نقشه‌راه توسعه فنی محصول موجَک، ثبت‌شده به‌صورت GitHub Issues در `massoudsh/motiva`. اولین کد اجرایی ریپو spike تله‌متری در `spikes/telemetry/` است.

## ساختار
۳ Milestone معادل ۳ فاز مسیر رشد محصول (طبق پیچ‌دک، اسلاید ۶) + لیبل‌های `phase-1-mvp` / `phase-2-scale` / `phase-3-platform` / `roadmap` روی هر issue.

## فاز ۱ — Design Partner MVP (Milestone #1)
هدف: اثبات کاهش زمان/هزینه لجستیک داخلی با یک کارخانه واقعی.

### Epic: #1 پایه فنی MVP (stack، مدل داده، احراز هویت، دسترسی سازمان/سایت)
sub-issueها به ترتیب ساخت:
1. #18 تصمیم stack (ADR-001)
2. #15 Fleet API: ربات، وضعیت، باتری، موقعیت، ingestion تله‌متری + retention
3. #16 نقشه کارخانه و مسیریابی سمت سرور
4. #14 مدیریت مأموریت
5. #17 UI عملیات زنده (جایگزینی داده شبیه‌سازی‌شده)
6. #5 یکپارچگی ERP/WMS: اول adapter امن و event contract، بعد کانکتور
7. #13 هشدارها، audit log، نقش‌ها و گزارش‌گیری

### سایر issueهای فاز ۱
- #2 موتور ناوبری خودران پویا روی ربات — ستون ۱
- #3 داشبورد مدیریت ناوگان (شارژ هوشمند، گزارش پیشرفته) — ستون ۳؛ هسته آن در #17
- #4 موتور بهینه‌سازی جریان مواد / تخصیص هوشمند — ستون ۲؛ تخصیص ساده در #14
- #6 استقرار پایلوت با اولین Design Partner

### تصمیم‌ها و یافته‌های فنی
- **ADR-001 (در حال بررسی، #18):** گزینه‌ها TypeScript / Python+React / Go+React. پیشنهاد اولیه: Python (FastAPI) + React + MQTT (EMQX) + TimescaleDB + WebSocket + Keycloak.
- **Spike تله‌متری (`spikes/telemetry/`):** ۵۰ ربات × ۱۰Hz ≈ ۴۹۰ msg/s با ۴٪ یک هسته و p99 ≈ ۶۱ms؛ ۵۰۰ ربات با ۱۹٪. نتیجه: ingestion پایتون کافی است. بروکر/DB واقعی هنوز تست نشده.
- **Retention (#15):** تله‌متری خام ۷ روز، ۱Hz ۹۰ روز، خلاصه‌ها ۲ سال، رویدادها ۱ سال. override پایلوت design partner: خام ۳۰ روز، ۱Hz کل پایلوت + ۹۰ روز، خلاصه و audit ۳ سال، snapshotهای baseline/KPI دائمی. (اعداد پیشنهادی، منتظر قرارداد #6)

## فاز ۲ — مقیاس‌گیری ناوگان (Milestone #2)
هدف: افزایش تعداد ربات‌ها و صنایع؛ ارزش به سمت لایه نرم‌افزار حرکت می‌کند.
- #7 معماری مقیاس‌پذیر چند-ناوگان و چند-سایت
- #8 سامانه onboarding و provisioning ربات جدید
- #9 گزارش‌گیری و تحلیل عملکرد برای مدیر عملیات

## فاز ۳ — پلتفرم جامع لجستیک (Milestone #3)
هدف: Digital Twin و یکپارچگی کامل با ERP/WMS/MES.
- #10 ماژول Digital Twin عملیاتی
- #11 یکپارچگی کامل و دوطرفه ERP/WMS/MES در مقیاس پلتفرم
- #12 API/SDK عمومی پلتفرم برای پارتنرها

## قرارداد
- هر issue جدید مرتبط با roadmap باید لیبل `roadmap` + یکی از `phase-1-mvp`/`phase-2-scale`/`phase-3-platform` و milestone متناظر بگیرد.
- کارهای فاز ۱ که به پایه فنی وابسته‌اند، sub-issue اپیک #1 می‌شوند؛ وابستگی‌های دقیق در بخش «وابستگی» توضیح هر issue ثبت می‌شوند.
- وقتی فاز جدیدی (فاز ۴+) تعریف شد، milestone و label جدید بساز و همین صفحه را آپدیت کن.
